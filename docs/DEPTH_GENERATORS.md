# Depth generator selection and candidates

Research checked 27 September 2026. **Automatic (recommended)** still uses Depth Anything V2 Small in both editions. The advanced chooser also offers an explicit V2 choice and, in the hosted browser edition, optional Depth Anything V3 Small. Depth Pro remains a research candidate.

| Candidate | Source and license | Deployment evidence | Decision |

| Depth Anything V2 Small | [Official V2 repository](https://github.com/DepthAnything/Depth-Anything-V2): 24.8 million parameters, Small checkpoint Apache 2.0. [Current browser ONNX model](https://huggingface.co/onnx-community/depth-anything-v2-small) documents a Transformers.js depth-estimation pipeline. | Already running through the browser's WebGPU/CPU fallback and the local Python model; the hosted container has no PyTorch. | Keep as Automatic and as the explicit, verified choice. |

## Contract for an additional adapter

1. The front end's `depthGenerators.ts` lists enabled adapters. `automatic` resolves to the recommended identifier; it is not a model. Each runtime explicitly advertises what it can run. The Studio and View-Master controls use the same catalog. The existing V2 browser adapter remains pinned and keeps its retry and WebGPU-to-CPU fallback. V3 is loaded in a separate chunk only if selected and tries WebGPU before browser CPU.
2. An adapter takes the original image and returns a depth map aligned to it, finite and normalized to **0–1, with higher values nearer**. V2's relative disparity already follows that convention. V3 predicts relative distance, which its browser adapter inversely maps to 8-bit nearness; constant maps become neutral gray and non-finite output is rejected. A metric-distance model such as Depth Pro needs an explicit distance-to-nearness conversion before stereo rendering; metre values and estimated camera intrinsics should be retained separately if ever needed.
3. The hosted edition runs each optional model in the browser. No model weights, PyTorch, or large inference dependencies enter `backend/requirements-hosted.txt` or the production Docker image. A browser adapter must handle its own model download, preprocessing, output conversion, device fallback, and user-facing failure stage. Do not infer usability from the existence of an ONNX file alone.
4. The local backend currently validates `GET /depth-map?generator=automatic|depth-anything-v2-small` and preserves calls without the parameter. Before a second local generator is registered, key the session's AI-depth cache by source **and generator**, route the selected identifier to its adapter, and invalidate active stereo/depth-edit caches only when a new depth map is actually produced. The current `depth_map_ai.npy` is a single V2 cache, so simply switching a model name in the endpoint would silently reuse old depth.
5. Keep the advanced chooser collapsed. In Studio, changing the choice regenerates an **unedited AI map** from the already loaded original image. Imported maps and maps with undo history remain active until the user explicitly presses the replacement button. The button can also rerun the selected generator without reuploading. View-Master's choice applies on the next reel build. Preserve imported depth and stereo-pair workflows.
6. The hosted generator posts its browser result to the session, then fetches the active depth without passing V3 through the local-only generator validator. The local edition's explicit regeneration endpoint forces a fresh V2 run from the retained original; the ordinary GET endpoint remains a cache/active-map read. A failed browser inference keeps any existing map visible and offers retry.

## Gates for future choices and device validation

- Verify checkpoint provenance and exact license; record the version, weight size, and separate optional download path.
- Compare V2 and the candidate on the **same images**, including a nearby object, distant background, thin edges, sky, and a non-photographic image. Confirm near/far orientation, alignment, uniform-depth handling, NaNs, and the actual stereo output, not just that inference returns an array.
- Exercise the browser adapter on WebGPU and the fallback browser CPU path with the project's supported devices. Check first download, warm cache, memory use, retry/error reporting, and that the hosted container stays lightweight. V3's device-specific performance and quality still require field testing; a model download or startup failure should leave the source image available for a retry or imported map.
- For a local-only adapter, test startup, inference, and memory on the intended local hardware. The 1.9 GB Depth Pro checkpoint alone does not establish usable Mac performance.
- Extend both the regression contract and the production-container smoke test when an adapter is enabled. No physical viewer, lens, filter, print, or hardware dimensions are inferred from model output.
